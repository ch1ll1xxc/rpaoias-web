## Состояние

| Компонент | Размер | Назначение |
|---|---:|---|
| R0..R15 | 16 × 16 бит | Регистры общего назначения. R0 не закреплен за нулем |
| PC | 16 бит | Байтовый адрес следующей исполняемой инструкции |
| IR | 32 бита | Последняя успешно исполненная машинная инструкция |
| ZF, SF, CF, OF | 4 бита | Результат предыдущей операции, которая изменяет флаги |
| ОЗУ | 4096 × 8 бит | Единая память кода и данных |
| HALTED | Состояние управления | Запрещает исполнение после HALT до сброса |

`steps`, исходные строки, таблица меток, трасса и лимит исполнения принадлежат эмулятору/отладчику. Это не доступные программе аппаратные регистры.

При сбросе РОН, IR и флаги обнуляются, `HALTED=False`, PC получает точку входа. ZF после сброса равен 0, хотя все РОН нулевые: флаг не является постоянной проверкой содержимого всех регистров. Он относится к результату операции.

## ОЗУ

Один адрес обозначает один байт. Поэтому 16-битное слово занимает два адреса, а 32-битная инструкция – четыре. Слово `0x1234` хранится как байты `34 12` по возрастающим адресам. Слово читается только с четного адреса, инструкция – с адреса, кратного четырем.

`Memory` содержит один `bytearray`. Процессор читает команды и данные из него. Доступ `MOV` к будущей инструкции может изменить ее; тест сам модифицирует NOP в HALT и проверяет, что fetch видит изменение. Это намеренная проверка единой памяти, не рекомендация писать самоменяющийся прикладной код.

Ассемблер запрещает случайное перекрытие областей при сборке. Аппаратной защиты кода в самой машине нет. Разделение `.org 0` для кода и `.org 0x400` для данных – соглашение программ, не два отдельных устройства памяти.

## Двухадресные операции

`ADD R1,R2` читает оба регистра и записывает сумму в R1. R2 сохраняется. Источником может быть литерал, но не слово ОЗУ: `ADD R1,[R2]` отвергается. Сначала нужно загрузить значение через `MOV`.

Особенность `MUL Rn,src`: n четный, результат занимает пару `R(n+1):Rn`. Первым явным операндом является младший регистр этой пары. Второй регистр результата определяется неявно. Например, `MUL R6,R7` читает прежние R6 и R7, затем заменяет оба на low/high результата. Адресность определяется явными операндами, а не количеством фактически измененных регистров.

Отдельного физического аккумулятора нет. В демонстрационных программах роль длинного аккумулятора выполняет R2:R1:R0; счетчик цикла – R5. Это объясняет назначение этих регистров при демонстрации, но не ограничивает остальные программы.

## Шаг

1. Fetch читает четыре байта по PC из единой памяти.
2. Decode выделяет поля и проверяет их допустимость.
3. Execute читает операнды и рассчитывает изменения.
4. Commit записывает результат и новое значение PC.

По умолчанию `PC_next = PC + 4`; выполненный переход заменяет его абсолютным адресом. HALT также увеличивает PC на 4, затем устанавливает HALTED. IR сохраняет именно HALT. Поэтому не следует интерпретировать память по новому PC как последнюю исполненную команду.

При ошибке инструкции, адреса или выравнивания step выбрасывает `CPUFault`, не изменяя регистры, флаги, PC, IR и ОЗУ. Это свойство данной модели. После последнего допустимого NOP PC может стать 4096; следующая выборка завершится ошибкой выхода за ОЗУ. Оборачивания адреса к нулю нет.

## Длинная арифметика

Знаковые операнды лежат в диапазоне -32768..32767. Их произведение помещается в 32 бита. Но сумма десяти произведений имеет границы:

```text
минимум: 10 × (-32768 × 32767)  = -10737090560
максимум: 10 × (-32768 × -32768) = 10737418240
```

34 знаковых бит недостаточно: максимум равен `2^33-1 = 8589934591`. 35 бит уже достаточно. Для целого числа 16-битных частей выбираем 48 бит.

Отрицательное 32-битное произведение расширяется до 48 бит старшим словом FFFF, положительное – словом 0000. Программа получает его через `SAR R8,15` от копии старшего слова произведения. Затем:

```asm
ADD R0, R6
ADC R1, R7
ADC R2, R8
```

`ADC` использует текущий перенос и формирует следующий. Между этими командами нельзя вставлять операции, меняющие CF, например шаг указателя. В CPU отсутствует операция «посчитать сумму массива» и отсутствует скрытый 48-битный аккумулятор, заменяющий эти три команды.

Склейка слов в Python int используется только для отображения и проверки результата. При реализации одной команды MUL Python умножает два значения; затем результат немедленно разбивается на два 16-битных регистра.
