# Система команд и машинная кодировка

Версия 0.1.0. Все точные правила в этом документе задают собственную учебную ISA.

## Формат инструкции

```text
31          24 23     20 19 18 17 16 15                     0
+-------------+---------+-----+-----+------------------------+
| opcode (8)  | reg (4) |mode | 00  | operand (16)           |
+-------------+---------+-----+-----+------------------------+
```

`reg` – номер регистра. `operand` – значение, адрес или номер регистра в зависимости от `mode`. Резервные биты обязательно нулевые; неправильная инструкция вызывает ошибку.

| mode | Смысл operand | Пример |
|---|---|---|
| 00 | Номер регистра 0..15 | `MOV R1,R2` |
| 01 | Непосредственные 16 бит | `MOV R1,12` |
| 10 | Байтовый адрес 16-битного слова | `MOV R1,[1024]` |
| 11 | Номер регистра с адресом слова | `MOV R1,[R2]` |

Пример: `MOV R2,12` кодируется как `0x0124000C`. В памяти little-endian находятся байты `0C 00 24 01`. Код другого учебного процессора из методички для этой же строки может отличаться: кодировка здесь своя.

## Команды

| ASM | opcode HEX | Действие | Флаги |
|---|---|---|---|
| `NOP` | 00 | Только PC += 4 | Сохраняются |
| `MOV Rn,src` | 01 | Копия src в Rn | Сохраняются |
| `MOV mem,Rn` | 02 | Копия Rn в слово ОЗУ | Сохраняются |
| `ADD Rn,src` | 10 | Rn = Rn + src, младшие 16 бит | Все |
| `ADC Rn,src` | 11 | Rn = Rn + src + входящий CF | Все |
| `SUB Rn,src` | 12 | Rn = Rn - src, младшие 16 бит | Все |
| `MUL Rn,src` | 13 | signed 16×16 -> R(n+1):Rn, n четный | По правилам MUL ниже |
| `CMP Rn,src` | 14 | Вычитание без записи результата | Все |
| `SAR Rn,count` | 15 | Арифметический сдвиг вправо | По правилам SAR ниже |
| `JMP addr` | 20 | PC = addr | Сохраняются |
| `JZ addr` | 21 | Переход при ZF=1 | Сохраняются |
| `JNZ addr` | 22 | Переход при ZF=0 | Сохраняются |
| `JC addr` | 23 | Переход при CF=1 | Сохраняются |
| `JNC addr` | 24 | Переход при CF=0 | Сохраняются |
| `JO addr` | 25 | Переход при OF=1 | Сохраняются |
| `JNO addr` | 26 | Переход при OF=0 | Сохраняются |
| `HALT` | FF | PC += 4; HALTED = True | Сохраняются |

Opcode 02 называется `STORE` в Python, но пользователь пишет обычный `MOV`. Поле `reg` у него содержит регистр-источник, `operand/mode` – приемник в ОЗУ. Это позволяет сохранить единый формат и 16-битное поле адреса без второй полной адресной части. Мнемоника `STORE` в исходном ассемблере не разрешена.

Для арифметики `src` допускает только регистр или непосредственное значение. Для чтения MOV – все четыре режима. Для записи MOV приемник – прямая или косвенно-регистровая память, источник – регистр. Пересылки память-память и литерал-память запрещены: используй промежуточный регистр.

В NOP/HALT `reg=0`, `mode=00`, `operand=0`. В переходах `reg=0`, `mode=01`, `operand` – абсолютный адрес в пределах ОЗУ, кратный четырем. Невыполненный условный переход оставляет обычный `PC+4`.

## Флаги ADD, ADC, SUB, CMP

ZF равен 1, когда сохраненные младшие 16 бит нулевые. SF равен их старшему биту.

Для ADD/ADC CF равен 1, когда беззнаковая сумма с входящим переносом превышает 65535. Для SUB/CMP CF равен 1 при беззнаковом `left < right`: потребовался заем. Это выбранная семантика CF.

OF равен 1, когда математический результат при знаковой интерпретации исходных 16-битных операндов не принадлежит -32768..32767. Для ADC входящий CF тоже входит в математический результат.

| Операция | Сохраненные биты | signed | CF | OF |
|---|---|---:|---:|---:|
| 32767 + 1 | 8000 | -32768 | 0 | 1 |
| FFFF + 1 | 0000 | 0 | 1 | 0 |
| 0 - 1 | FFFF | -1 | 1 | 0 |
| 8000 - 1 | 7FFF | 32767 | 0 | 1 |

Флаг ZF после последнего ADC относится к его 16-битному результату, **не ко всему 48-битному числу**. Нулевое значение длинного числа нужно проверять по всем частям. В демонстрационных циклах JNZ проверяет флаг последнего SUB счетчика.

## MUL

Оба источника сначала читаются как signed 16. Их произведение записывается полностью: младшие биты в Rn, старшие – в R(n+1). Поэтому разрешены только R0, R2, ..., R14 как первый операнд.

ZF у MUL относится ко всему произведению; SF – к его знаку. CF и OF одинаковы и показывают, что полное произведение не помещается в одно знаковое 16-битное слово. Никакие биты произведения при этом не теряются.

## SAR

`count` – значение 0..15, непосредственное либо прочитанное из регистра. При 0 регистр и флаги сохраняются. При 1..15 слева повторяется знаковый бит, CF получает последний вытесненный справа бит, OF=0, ZF/SF относятся к результату.

В частности, `SAR Rn,15` превращает исходное число в 0000 или FFFF и используется для знакового расширения. Это не циклический сдвиг и не перенос CF обратно в слово.
