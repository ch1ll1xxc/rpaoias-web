# Ассемблер

Исходник – UTF-8, без зависимости от регистра букв в именах и командах. Идентификаторы: латинские буквы, цифры и `_`, первый символ не цифра. Комментарии могут быть на русском.

## Запись

```asm
.entry start
.org 0
start:
    MOV R1, ARRAY
    MOV R2, [R1]
    ADD R1, 2
    JNZ start
    HALT

.org 0x0400
ARRAY:
    .word 2, -1, 7
```

Это пример синтаксиса, не алгоритм обработки массива: JNZ здесь увидит флаги ADD указателя. Рабочие алгоритмы находятся в `src/rpaoias/programs/`.

Метка пишется как `name:`. Она может занимать отдельную строку либо предшествовать команде или `.word`. Метка не генерирует байты. Регистр нельзя использовать как имя метки. Дубликаты меток запрещены.

Комментарии начинаются с `;` или `//` и продолжаются до конца строки. Операнды разделяются запятыми.

| Запись | Значение |
|---|---|
| `12`, `-12`, `+12` | Десятичное число |
| `0xFF00` | Шестнадцатеричное число |
| `0b1010` | Двоичное число |
| `ARRAY` | Адрес метки |
| `RESULT+2` | Адрес со смещением в байтах |
| `[ARRAY]` | Слово ОЗУ по адресу метки |
| `[R3]` | Слово ОЗУ по адресу из регистра R3 |

Поддерживаются выражения с `+` и `-`, например `RESULT+2` и `12-4`. Умножения, скобочных арифметических выражений, макросов и вызовов Python нет. `[R3+2]` тоже не поддерживается: для косвенно-регистровой адресации внутри скобок должен быть ровно регистр. Смещение можно предварительно прибавить к самому регистру.

Литералы и `.word` принимают -32768..65535. Отрицательная десятичная запись преобразуется в дополнительный код. Прямые адреса не могут быть отрицательными, должны быть четными и помещаться в ОЗУ. Адрес перехода кратен четырем.

## Директивы

`.org number` устанавливает текущий байтовый адрес размещения. Разрешено только числовое выражение без меток. Следующая инструкция должна оказаться на адресе, кратном 4; данные `.word` – на четном. Метка на одной строке с `.org` запрещена, чтобы ее адрес не зависел от неочевидного порядка действий. Размести ее следующей строкой.

`.word value, ...` записывает одно или несколько 16-битных слов в little-endian. Каждое значение занимает 2 байта.

`.entry expression` задает стартовый PC. Встречается не более одного раза. По умолчанию вход – адрес 0. На адресе входа должна быть собранная инструкция.

## Почему два прохода

На первом проходе известен размер каждой строки: инструкция 4 байта, `.word` – по 2 байта на значение. Поэтому можно вычислить адрес каждой метки, не зная машинного кода инструкции.

На втором проходе разрешаются ссылки на метки и кодируются инструкции. Переход вперед уже имеет известный адрес. Ошибки обнаруживаются до выдачи `Program`, поэтому не существует наружного состояния «половина программы успешно собрана».

Методичка, стр. 54, показывает разрешение будущих ссылок через таблицу неразрешенных мест. Два прохода в нашем проекте – другой конкретный способ решить ту же задачу.

## Листинг и ОЗУ

`Program.image` – готовые 4096 байт памяти. `Program.entry` – стартовый адрес. `symbols` и `listing` нужны человеку, а не исполнителю.

CPU получает image/entry и заново декодирует машинный код при каждом fetch. Он не берет готовую команду из `listing`. Поэтому запись в кодовую часть ОЗУ действительно влияет на дальнейшее исполнение.
