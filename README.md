# РПАО ИАС: эмулятор для варианта 2

Версия процессора: **0.1.0**. Интерфейс с вкладками: **16 октября 2026 года**.

Двухадресный учебный процессор с единой памятью команд и данных. Python моделирует процессор; программы для этого процессора написаны на нашем ассемблере. Это два разных уровня исполнения.

Задание из методички: сумма элементов массива и «свертка» двух массивов по 10 знаковых элементов, с длинной арифметикой во втором задании. В проекте реализуется именно формула (4.1) из методички: `S = sum(A[i] * B[i])`.

**Интерфейс с вкладками:** редактор, исполнение, регистры, память и история занимают отдельные страницы. Декоративного баннера нет. Есть разбор шагов с фактическими значениями до и после команды. Запуск, установка правки и управление описаны в [docs/ui-tabs.md](docs/ui-tabs.md).

**Проверка:** 424 теста прошли. Три модуля графических тестов пропущены из-за отсутствия PySide6. Запуск нового окна и проверка на Windows в среде подготовки не выполнены. Подробности: [docs/ui-tabs-verification.md](docs/ui-tabs-verification.md).

## Запуск

Открой терминал в каталоге, где лежит `pyproject.toml`. Основная версия интерпретатора для проекта – Python 3.13, она указана в `.python-version`.

### С uv

Если uv еще не установлен, его можно установить через доступный Python:

```powershell
python -m pip install uv
```

Оконный отладчик:

```powershell
uv run --extra gui rpaoias gui
```

При первом запуске uv создает окружение и загружает пакеты. Здесь нужен доступ к серверу пакетов. После первого успешного разрешения зависимостей появится `uv.lock`: его стоит сохранить в Git. В поставке lock-файла нет, потому что в среде подготовки разрешение зависимостей не завершилось. Команды uv сверены с официальной документацией, ссылки находятся в [docs/sources.md](docs/sources.md).

Без графики:

```powershell
uv run rpaoias run sum
uv run rpaoias run dot_product
uv run rpaoias run carry --trace
uv run rpaoias assemble sum
```

Проверки:

```powershell
uv run pytest -q
uv run ruff check .
```

Графические smoke-тесты включаются установкой extra:

```powershell
uv run --extra gui pytest -q
```

Тестовый модуль сам использует платформу Qt `offscreen`, если `QT_QPA_PLATFORM` не задана. Это не заменяет ручную проверку окна на реальном рабочем столе.

### Уже есть Python, но нет доступа к загрузке пакетов

Для ядра и CLI не нужны сторонние зависимости. В PowerShell:

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m rpaoias run sum
python -m rpaoias run dot_product
python -m rpaoias run carry --trace
```

В bash:

```bash
PYTHONPATH=src python -m rpaoias run sum
```

Это реальное выполнение того же ядра, не отдельная упрощенная реализация. Для запуска pytest сам pytest должен быть установлен.

## Что открывать первым

Начни со встроенного примера `carry`: четыре первые команды показывают, зачем нужен перенос между регистрами.

```powershell
uv run rpaoias run carry --trace
```

В GUI выбери «Перенос ADD/ADC», нажми «Загрузить пример» и выполняй по одному шагу. После `ADD R0,1` младшее слово обнулится, а `CF` станет единицей. После `ADC R1,0` старшее слово станет единицей. Пара `R1:R0` представляет 65536.

Порядок чтения исходников:

| Файл | Что в нем разбирать |
|---|---|
| `src/rpaoias/cpu/word.py` | Ограничение разрядности, дополнительный код, интерпретация битов |
| `src/rpaoias/cpu/alu.py` | ADD/ADC, заем, CF/OF, знаковое расширение, произведение |
| `src/rpaoias/isa/instruction.py` | Допустимые команды и сочетания операндов |
| `src/rpaoias/isa/codec.py` | 32-битная инструкция, маски, сдвиги, резервные поля |
| `src/rpaoias/cpu/memory.py` | Единая байтовая ОЗУ, little-endian, выравнивание |
| `src/rpaoias/cpu/processor.py` | Полный шаг CPU и публикация изменений состояния |
| `src/rpaoias/assembler/` | Токены, строки, два прохода, метки, генерация машинного кода |
| `src/rpaoias/programs/` | Две программы задания и два коротких учебных опыта |
| `src/rpaoias/ui/window.py` | Наблюдение за CPU, таймер, шаг, сброс, защита от устаревшего исходника |
| `tests/` | Исполняемые примеры ожидаемого поведения и граничных случаев |

Важные теоретические места объяснены в docstring и комментариях непосредственно рядом с кодом. Ссылки на методичку используют **печатную нумерацию страниц**, а не номер страницы в PDF-просмотрщике.

## Выбранная машина

| Свойство | Решение проекта |
|---|---|
| Данные и РОН | 16 бит; R0..R15 |
| Память | Единый массив 4096 байт, little-endian |
| Слово данных | 2 байта, четный адрес |
| Инструкция | 4 байта, адрес кратен 4 |
| PC / IR | 16-битный адрес / 32-битная инструкция |
| Флаги | ZF, SF, CF, OF |
| Арифметика | Два явных операнда; первый также приемник |
| Умножение | `MUL Rn,src` записывает 32 бита в `R(n+1):Rn`; n четный |
| Длинный накопитель | R2:R1:R0, 48 бит; складывается программно через ADD/ADC |
| Совместимость | Собственная ISA, не x86 и не RISC-V |

Требования задания и наши решения разделены в [docs/requirements.md](docs/requirements.md). Полная программная модель – [docs/cpu.md](docs/cpu.md), правила команд – [docs/isa.md](docs/isa.md), синтаксис – [docs/assembler.md](docs/assembler.md).

## Интерфейс

Основные вкладки: «Программа», «Исполнение», «Регистры», «Память», «История». Внутренние вкладки разделяют исходник и листинг, разбор и поля команды, ОЗУ и обращения к ней. Панель управления и строка состояния остаются доступными на всех вкладках.
Веб-лаборатория использует официальные CSS-тему и основу Gravity UI UIKit 8.0 локально, без сетевой загрузки; лицензия поставляется рядом со стилями. Переходы интерфейса короткие и отключаются при `prefers-reduced-motion`.

«Показать разбор» последовательно показывает пояснения завершенного шага. Это не повторное выполнение CPU. История хранит до 1000 завершенных команд и позволяет открыть любую из них без отката текущего состояния.

Редактор содержит обычный текст `.asm`. «Собрать» переводит его в машинный код и создает новый образ ОЗУ. «Шаг» исполняет одну инструкцию. «Пуск» вызывает те же шаги по таймеру, «Пауза» прекращает вызовы. «Сброс CPU» восстанавливает и регистры, и исходную память.

Показываются регистры в HEX, signed и unsigned, PC, IR, флаги, отдельные поля инструкции, листинг и трасса. Подсветка исходника относится к следующей команде по PC. Панель IR относится к последней исполненной команде. Это намеренно разные вещи.

После правки исходника исполнение заблокировано до новой сборки. Ошибки сборки и исполнения показываются внизу окна. Сиреневым фоном и полужирным текстом отмечаются значения, изменившиеся на последнем шаге.

Память показывается страницами по 256 байт. Кнопка «К RESULT» выбирает страницу результата. Все таблицы только для чтения: для изменения начальных данных отредактируй `.word` в исходнике и собери программу заново.

## Программы и ожидаемые результаты

| Пример | Результат | Исполнено инструкций |
|---|---:|---:|
| `sum` | 65459 | 105 |
| `dot_product` | 2947418113 | 141 |
| `carry` | 65536 | 8 |
| `overflow` | R0=8000; signed=-32768; CF=0, OF=1 | 3 |

У двух программ задания `R15=0` означает успешное завершение; `R15=1` – неверный заголовок массива. Это соглашение программ, не встроенная функция CPU. `sum` принимает длину 0..15, `dot_product` – одинаковые длины 0..10; нулевые и короткие массивы добавлены для тестов. Для демонстрации варианта 2 оставлены 10 элементов, как и требуется во втором задании.

Первое слово каждого массива хранит длину. Оно не участвует в сумме или произведении. `RESULT` занимает три слова в порядке low, middle, high. У отдельных частей длинного числа нет самостоятельного знакового смысла: результат читается по всем 48 битам.

Свой файл запускается так:

```powershell
uv run rpaoias run my_program.asm --trace
uv run rpaoias assemble my_program.asm -o memory.bin
```

`memory.bin` – полный образ ОЗУ, а не исполняемый файл Windows. Команда `run` принимает исходный `.asm`, а не `.bin`. Точка входа из `.entry` в самом `.bin` не хранится. Для результата иной ширины используй `--words`, например `--result answer --words 2`.

## Что пока не сделано

Не подготовлен окончательный отчет с титульным листом и личными реквизитами. Нет установщика, автономного `.exe`, точек останова и редактирования памяти непосредственно в таблице. Конвейер, кеш, прерывания и периферия не входят в выбранную базовую модель.

Перед защитой нужно проверить GUI на целевом ПК и согласовать собственную ISA с преподавателем. Маршрут короткого разбора и контрольные вопросы находятся в [docs/theory.md](docs/theory.md).
